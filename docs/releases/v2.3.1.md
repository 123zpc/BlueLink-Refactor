# BlueLink v2.3.1（测试版，未正式发布）

针对 v2.3.0 真机首测（经典蓝牙扫描已在真机成功列出 5 台设备）反馈的四项问题逐项修复。本包仍为**测试版**：经典蓝牙的配对、连接、传输速度等运行时行为仍待真机复验，确认后再走正式发版。

## 本版修复

1. **连接页设备列表滚动**：设备较多时连接页被整个顶出、划不回来的问题已修。连接页改为固定头部（状态行、本机设备卡、列表标题）+ 设备列表独立滚动区，设备再多也只在列表内部滚动，页面不再被顶掉。
2. **经典蓝牙服务端口占用（WSA 10048）**：
   - 新增单实例保护：应用已在托盘运行时再次点图标，只唤出已有窗口，不再启动第二个进程（双开是抢占端口的常见来源）；
   - 若端口仍被其他程序占用（如老版本正在运行），状态行改为明确人话提示：「端口被其他程序占用（多半是另一个 BlueLink 或老版本正在运行），关掉它再重启本应用；你主动连接别人不受影响」，原始错误完整保留在运行日志中。
3. **小图标可读性**：`.ico` 的 16/20/24/32 小帧笔画适度加粗（48 及以上帧与原设计逐字节一致，未改动），`32x32.png` 同步处理。
   - 说明：v2.3.0 真机截图里任务栏显示的「蓝方块+白圆环」是 **Windows 图标缓存残留的旧版（v2.2.2 之前）图标**——现行安装包内的图标资源经逐帧核对就是定版双链节，没有装错。新包安装后若仍显示旧图标，是本机缓存未刷新，可重启资源管理器或重启系统解决，与安装包无关。
4. **运行日志入口**（位置确认，无代码改动）：设置 → 存储 → 「运行日志」一行有日志目录路径与「打开目录」按钮；日志文件为数据目录下 `logs/bluelink-YYYY-MM-DD.log`，按天滚动。Windows 下打开目录走系统资源管理器，代码已复核无误。

## Windows 安装包带 SimpleBLE

- 本版 **Windows 安装包已编译带 SimpleBLE**（第三个传输实现）：设置里连点版本号三次打开开发者模式后，连接页的传输切换中可选择 SimpleBLE。
- Linux / macOS 安装包本版仍未启用 SimpleBLE（选了会如实提示并回落经典蓝牙），后续版本再评估。
- 注意：SimpleBLE 服务端只在「启动应用时已选中 SimpleBLE」才会拉起广播；在开发者模式里切换到 SimpleBLE 后需**重启应用**，本机才会被对方经 SimpleBLE 发现（主动扫描/连接对方立即生效）。

## 已知事项

- **经典蓝牙设备列表没有信号格**：经查证，Windows 官方接口不提供经典蓝牙 Inquiry 的 RSSI——`BLUETOOTH_DEVICE_INFO`（经典查询结果结构）与驱动层 `BTH_DEVICE_INFO`/`BTH_RADIO_IN_RANGE` 均无 RSSI 字段，WinRT 的经典 `BluetoothDevice` 类也没有信号属性；`System.Devices.Aep.SignalStrength` 官方文档只写「仅适用于部分协议」，未证实对经典蓝牙填充；连接后的 RSSI 同样没有面向应用的官方接口（`IOCTL_BTH_HCI_VENDOR_COMMAND` 按文档仅限厂商私有命令）。因此经典行不显示信号格（不造假数据）；BLE 行照常按 RSSI 显示。
- **本包内置 SCANPROBE 扫描诊断（仅日志）**：为定案上面那条「AEP 属性对经典设备到底有没有值」，本包在扫描时把三套接口能拿到的全部字段写进运行日志（不动界面、不改扫描结果）：经典 Inquiry 原始结构全字段、WinRT DeviceWatcher 枚举经典设备并申请 AEP 属性全集逐项记录（重点 SignalStrength，其余 IsPaired/CanPair/IsConnected/厂商/型号等一并记录，有值记值、没有明确标「（空）」）、BLE 广播全字段（RSSI/发射功率/服务 UUID/厂商数据等）。日志里搜 **SCANPROBE** 即可定位，逐设备有「设备开始/设备结束」分段。真机跑一次经典扫描后把日志发回，就能据实测定经典信号格做不做。
- 经典蓝牙全部运行时行为（扫描已通过；配对弹窗、配对后自动直连、SDP 直连、聊天/文件传输与实际速度、经典记录的一键重连）仍待真机复验。
- 安装包未签名，Windows 首次运行可能出现 SmartScreen 提示。
