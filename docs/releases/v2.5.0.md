# BlueLink v2.5.0（测试版，未正式发布）

本版是一轮大修：新增**剪贴板同步**；修掉**点「取消」没反应**（并顺带揪出一个存量缺陷——旧版「断开连接」其实没有真关掉底层连接，对方会一直以为还连着）；修**小窗口布局挤压**与**输码时本机连接码被挤出屏幕**；蓝牙列表**不再抖动、同名设备合并成一条**；经典蓝牙的**已配对设备开始显示信号格**；BLE 连接全程加**分步日志**，连不上时凭日志一次定案。仍为**测试版**：正式发版等经典蓝牙真机连接/配对/传文件确认后另行进行。

## 1. 剪贴板同步（新功能）

连接的两台电脑之间双向同步剪贴板（文字 + 图片）：

- **开关默认关**，在「设置 → 剪贴板同步」打开；**双方都开启才生效**——对方没开，你复制什么都不会动他的剪贴板；你没开，对方发来的内容也会被忽略。设置页会显示当前状态（未开启 / 等待连接 / 对方未开启 / 已同步）。
- 开关打开后，你当前剪贴板里的内容会自动补同步一次；之后任一端复制，另一端随之更新（约 1 秒内）。
- **单份上限 2MB**（文字按字节、图片按发送大小算）：超限只跳过并记日志，不弹提示打扰。
- 防回环：收到并写入的内容不会被再发回去，不会来回震荡。
- 本地已用双实例（局域网开发者模式）完整实测九项：默认关、单开不互通、开启补同步、文字双向、图片双向（像素哈希一致）、防回环计数、超限跳过、关开关后忽略、开回恢复——全过，录像存档。**真机蓝牙链路上的同步待复测**（本地是局域网验的，协议与链路无关，预期一致）。

## 2. 点「取消」终于有效（附带修好「断开不彻底」）

- **旧问题**：输码卡与连接中的「取消」点了没反应——旧代码在连接中把取消按钮禁用了，而且连接尝试一旦开始就没法作废，只能干等超时。
- **修法**：点取消**立即**退回浏览态；后台那次尝试被作废——它就算迟到连上，也会立即自行断开，不进聊天页、不记「上次连接」。局域网连接同样加了取消按钮；蓝牙/BLE 连接统一加了 20 秒超时，卡住自动判失败并给人话原因（如「握手超时：对方未在 20 秒内响应」「BLE 连接超时：卡在步骤2/6（无线电连接）」）。
- **顺带揪出的存量缺陷**：旧版「断开连接」只清了本机会话状态、没有真关底层连接，对方会一直显示还连着。本版断开会真正关闭连接，对方随之回到未连接。本地实测：连一个不应答的端点→点取消→界面当场恢复、等满超时后仍未连接；经 3 秒延迟代理连真机→途中取消→握手迟到完成后本机自行断开、对方随之掉线。

## 3. 小窗口布局修复

窗口较窄（约 950px）时展开会话列表，旧版四列抢宽：连接页卡片被压窄、按钮文字竖排、标题乱折行。本版：

- 窗口宽 ≤1100px 时，会话列表改成**浮层抽屉**（盖在内容之上、带阴影），不再挤压主区；悬浮开关按钮跟到抽屉右缘。宽窗保持原来的推开式布局。
- 同断点下连接页两栏改**单栏堆叠**（设备列表在上、卡片顺流而下、整页纵向滚动）；「扫描/停止」按钮与「附近的设备 N 台」等标题不再折行。
- 聊天页同口径（抽屉浮层 + 对话区全宽可用）；1180×760 正常尺寸下各页与上一版逐图比对一致，无回退。修前/修后对照截图存档。

## 4. 输码时本机连接码不再被挤走

旧版点「连接」进入输码态后，本机设备卡被挤到右栏下方、默认窗口里看不见，要滚动才找得到。本版输码卡就排在本机设备卡正上方，**输码 / 连接中 / 连接失败时，本机连接码在第一屏内直接可见**；小窗口单栏时顺序同样合理（设备列表 → 输码卡 → 本机卡）。

## 5. 蓝牙列表：不抖动、同名合并、只列能连的

针对真机反馈的「列表上下抖动剧烈、同一设备出现两条（一条 0 格一条满格）、点谁都连不上」：

- **抖动根因**是旧版按实时信号强度反复重排。本版改为**按首次发现顺序**排列，信号只原地更新数值与格数；界面刷新加节流（内容没变不重建列表）。
- **同名合并**：同一台机器会用多个轮换的蓝牙地址广播（系统隐私机制），旧版每个地址一条。本版同名身份合并成一条（信号取最强的那个身份）。没有名字的「未知设备」不参与合并（无法证明是同一台，避免藏掉真设备）。
- **BLE 列表本来就只列带 BlueLink 服务的设备**（代码与真机日志互证：过滤没有缺陷；此前 BLE 扫到 0 台那轮，是对端那段时间广播没发出来——同一时段 SimpleBLE 也要等对端广播恢复后才扫到）。点到没有 BlueLink 服务的设备必然连不上，这类设备现在不会出现在 BLE 列表里。
- 日志取证细节（两台机器的全天日志逐行核对）在 QA 记录里。

## 6. 经典蓝牙：已配对设备显示信号格

真机日志定案：系统 AEP 接口能拿到已配对设备的信号强度。本版把该探针转成正式数据通路：经典扫描时按蓝牙地址把信号值并入列表，复用现有格数规则（-55/-65/-75/-85 分档）。刻度护栏：只有像样的负 dBm 值（≤ -25）才画格；连接状态下系统会给一个小正数（相对刻度、不是 dBm），那种值先不画格、只记日志攒样本。没配对过的陌生设备系统不给信号，照旧无格。**真机复验点**：已配对过的电脑在经典列表里应出现信号格。

## 7. BLE 连接分步日志（请协助一次复测，一次定案）

旧版连接过程**完全不记日志**（两台机器的全天日志里连接尝试零记录），连不上只能猜。本版给 BLE 与 SimpleBLE 的连接全程打分步日志，每步带时间戳与耗时：

- 发起端搜 **「连接步骤」**：步骤1 开始（带目标名称/地址/信号——点到哪条身份一看便知）→ 步骤2 无线电连接 → 步骤3 服务发现（列出找到的全部服务 UUID）→ 步骤4 特征值齐不齐 + 订阅 → 步骤5/6 搜 **「握手步骤」**（Hello 发出/收到回应）。
- 失败搜 **「连接失败于步骤」**：会写明卡在第几步、等了多久、底层错误原文。
- 对端（被连的一台）搜 **「服务端：」**：服务发布是否成功、广播内容是什么、广播状态确认结果、有没有设备连入并订阅；再搜「握手步骤」看对端有没有收到 Hello。
- **请协助复测**：两台都装 v2.5.0 → 对端保持 BlueLink 开着 → 本机切 BLE 传输点一次连接 VE2P2MLC（成败都行）→ 两台的当天日志都发回。凭这六步对账即可指认卡点，不用再来回试。

## 8. SimpleBLE 广播启动修复 + 内置 BLE 广播真状态验证

- **SimpleBLE 广播启动失败**（两台机器、两个适配器、每次以 SimpleBLE 启动必现 `bad exception`）：头号嫌疑是启动时内置 BLE 服务端与 SimpleBLE 服务端为同一个服务注册了两个 GATT 提供者、互相冲突。本版改为：**选了 SimpleBLE 就只起 SimpleBLE 的服务端**，跳过内置 BLE 广播（经典蓝牙服务端不受影响）；广播启动失败自动重试 3 次（间隔递增），每次结果记日志；状态行如实显示「SimpleBLE 启动失败：<原因>，已回落经典蓝牙」。**真机复验点**：两台装 v2.5.0、以 SimpleBLE 启动，看状态卡 SimpleBLE 行是否变绿、日志还有没有「启动失败（第 N 次）」。
- **内置 BLE 服务端**同样补上真状态验证：库只负责「发起广播请求」，广播被系统中止时旧版无从知晓、状态行照样报已开启。本版启动后轮询确认真处于广播状态（5 秒内），确认不了就如实报错并记日志；服务发布成功、广播内容、有设备连入等关键事件全部记日志（搜「服务端：」）。
- SimpleBLE 初始化失败与「未编入回落」在日志里分开记录，状态卡给人话原因，不再无声无息。
