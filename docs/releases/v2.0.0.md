# BlueLink v2.0.0 发布说明（蓝牙版）

> **本版未对外发布，已由 v2.0.1 取代。** 原因：发布前 GUI 实测发现 Tauri 权限配置缺失（无 capabilities 文件），前端事件订阅被拒绝，连接成功后界面不自动切到聊天页、新消息不实时刷新——后端链路正常，问题在界面事件层。修复与复验记录见 docs/releases/v2.0.1.md。GitHub 上的 v2.0.0 草稿与标签已删除，从未正式发布。

发布日期：2026-11-18 ｜ 类型：客户交付版（大版本）

## 本版定版事项

- **产品通道定版为蓝牙**：v1.x 的局域网实现不符合产品定义（原版 BlueLink 即蓝牙离线通讯），本版起每个交付版本都必须是实际可用的蓝牙版本。局域网仅保留为开发测试通道，入口在「设置 → 开发者模式」（默认关闭，开启后连接页出现局域网测试区，命令层对未开启状态的局域网调用一律拒绝）。
- **界面按大厂桌面通讯规范重做三轮**：全套 SVG 线性图标（清除 v1.x 的 emoji 图标）、头像体系、消息分组、文件卡片、深色模式三档切换、命令面板/抽屉/浮层阴影与状态完善。设计规范同步更新为 DESIGN.md v0.2。

## 蓝牙实现

- 传输层新增 BLE 后端（crates/transport/src/ble.rs）：
  - 服务端：ble-peripheral-rust（Linux/BlueZ、Windows/WinRT、macOS/CoreBluetooth）注册 GATT 服务并广播，本机可被附近设备发现、连入。
  - 中心端：btleplug 按服务 UUID 扫描、连接、订阅通知。
  - 数据面：INBOX 特征（写）+ OUTBOX 特征（通知）组成全双工字节流，ATT 层按 200 字节分片，长度前缀协议帧在流上重组，与既有服务层（握手校验连接码、聊天、文件断点续传、AI 代理）完全同构，服务层零改动。
- 连接流程：打开应用即开始广播 → 对方在「附近的设备」列表点选本机 → 输入本机连接码 → 握手校验通过后进入聊天。发起方在本机扫描列表点选对方并输入对方连接码。
- 应用启动时自动装配蓝牙运行时；无适配器或未开启时应用照常启动，连接页如实提示。

## 界面（UI 三轮迭代）

- 第一轮：SVG 图标系统（24 视图框、1.8px 描边）替换全部 emoji；设计令牌 v2（灰阶层级、悬停/选中态、焦点环）；三栏布局密度与品牌区重做；头像体系落地。
- 第二轮：消息分组（同发送者 5 分钟内收起头像）；文件卡片（图标块 + 名称 + 进度）；AI 页头像与流式行统一；深色模式（浅/深/跟随系统）；连接页改为蓝牙扫描配对页（状态点、本机设备卡、设备列表、连接码输入行）；设置页补外观与开发者分组；空状态文案齐备。
- 第三轮：微交互与细节走查（按钮/列表悬停与按下态、滚动条、命令面板搜索头、置顶栏图标化、引用条样式），全页面截图走查后修正。

## 验证状态（如实记录）

- 自动化：全工作区单元/集成测试与 clippy 待填入本版结果；新增 BLE 通道流测试（200/64 字节分片下 300KB 帧无损重组）。
- 本机：Linux 安装包构建、安装、启动与各页面截图走查（见随附截图）。
- **未验证项（需要用户真机）**：两台真实设备间的蓝牙配对、聊天与文件传输。本开发机（虚拟机）无蓝牙硬件，无法完成真机链路验证；请在两台带蓝牙的设备（Windows/Linux/macOS）上安装本版后互连验收。
- 已知限制：BLE 带宽有限，大文件传输速度低于局域网/Wi-Fi 通道（功能可用，速度受蓝牙物理层限制）；安装包未签名，Windows SmartScreen / macOS Gatekeeper 首次运行会提示。
