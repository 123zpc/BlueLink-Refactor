# BlueLink v2.5.2（测试版，未正式发布）

本版内容较多：**软件更新**落地（手动检查、一键下载安装重启）；**Windows 系统通知可点击回窗**；一批 v2.5.1 真机反馈的修复——**经典蓝牙扫描 0 台**（在场门误杀）、**内置 BLE 会话断联**、**置顶没反馈**、**复制文件只能复制到路径**；另有**设备 ID 改为机器绑定**（连接码最后变一次）、**粘贴文件与多文件批量发送**、**文件压缩升级 zstd**、**发送收尾提速**，以及一条查实并修好的 **AI 转发链故障**。仍为**测试版**，正式发版的一次机会未动用。

## 1. 手动检查更新 + 一键自动更新（新功能）

- **只手动触发**：设置页「关于」区有「检查更新」按钮与状态行。应用平时绝不自动联网检查——不点，就不查。
- **流程**：点检查 → 查最新**已正式发布**版本（草稿测试包不会被推送）→ 已是最新会明确提示「已是最新版本」；发现新版弹窗显示新版本号与更新说明节选，点「立即更新」开始下载（进度条；下载中可取消——取消后不会安装）；下载完成再确认一次，点「安装并重启」自动完成安装并重新打开 BlueLink。
- **安全**：更新包带数字签名，应用内置公钥校验，签名不对的包会被拒绝安装（本地实测中故意用错公钥的包会被拦下并提示「签名校验失败」）。检查不到（如暂无已发布版或网络不可用）会如实提示。
- **本地全链已实测**：用本地自签服务器完整走通 检查 → 发现新版弹窗 → 下载进度 → 验签 → 安装并重启 → 版本号变新版 → 再查提示已是最新（证据见 QA 第 75 条）。
- **注意**：本功能从本版起才内置——装上 v2.5.2 之后，下一个正式版发布时就能在应用里点更新了；v2.5.2 本身仍需从发布页手动下载安装一次。

## 2. Windows：点系统通知回窗并打开会话

- **旧缺口**（v2.5.1 如实记录）：系统通知只能看、不能点——官方通知插件在桌面端不提供点击回调。
- **本版（仅 Windows）**：消息通知改走 Windows 原生 WinRT 通知并注册点击激活：点通知 → 应用窗口从托盘/最小化/后台回到前台 → 直接打开对应会话。应用标识与激活器写在当前用户注册表里（免管理员、免改安装器）。
- **不变的部分**：通知开关默认开、三态行为（正看着应用时不弹、关了永不弹）、标题=对方名称、正文节选与 [文件]/[图片] 占位口径，与 v2.5.1 一致。
- **其他平台**：Linux / macOS 仍走官方通知插件发送，能弹不能点开，如实标注。Windows 真机上的实际点击效果待复验（见文末清单）。

## 3. 纠正 v2.5.1 的窗口定版

- v2.5.1 把窗口默认与最小尺寸一起抬到了 1120×740，做拧了。**本版改回：默认 = 最小 = 900×600**（打开就是最小尺寸），与 v2.5.0 及以前一致。
- 连接页在这个尺寸下重新做了紧凑排布：浏览态与输码态都整页不滚动、全部卡片可见可操作（本地实测截图见 QA）。其他页面在 900×600 下顺查无破版。

## 4. 经典蓝牙扫描 0 台——已修复

- **症状**：v2.5.1 真机经典扫描明明枚举到 9 台设备，列表却是 0 台。
- **根因**：v2.5.1 新加的「在场门」拿设备的时间戳与本轮扫描起点比对，但两侧时钟基准不一致（一个是 UTC、一个是本地时间，差约 8 小时），把本轮真在场的设备全判成了「很久没出现」而滤掉。
- **修法**：枚举本轮返回本身即在场证据——没有时间戳、或时间戳在任一时钟读法下属于本轮/近期的设备一律放行；只有在两种读法下都明确古老的已配对设备才滤掉。宁可放过，不再误杀。修后真机扫描计数行对账待复验（见文末清单）。

## 5. 内置 BLE 断联改进

- **加了应用层心跳**：连接后每 5 秒互发心跳帧，连续约 15 秒收不到对方任何数据即判死断开，两边察觉差从「一边断了另一边半天没反应」（实测差约 28 秒）压进几秒；断开原因分开落字（链路结束 / 接收出错 / 心跳判死 / 用户主动 / 被新连接替换），不再统一打标误导排查。文件传输进行中不判死（靠传输自身的超时兜底）。
- **无线电瞬态抖动不拆链**：蓝牙无线电状态的瞬时波动（例如同适配器同时在扫描）此前会让服务端会话被无声拆掉，现改为只记日志、继续观察，不动会话。
- **其他**：服务端通知超时不再留下半死会话；客户端重连时「设备已不在扫描范围内」的陈旧缓存误报已修（短暂等待重查再下结论）。

## 6. 置顶反馈补齐

- 查实：v2.5.1 的置顶其实是生效的，但**没有任何反馈**——没提示、按钮不变样、菜单文案不变，看起来就像没起效。
- 本版：点置顶立刻弹提示「已置顶」/「已取消置顶」；置顶栏当场增删（不用切页或重启）；悬停按钮与右键菜单按当前状态显示「置顶」/「取消置顶」；重启后置顶仍在（本地实测通过）。

## 7. 复制文件改为复制文件本体（Windows）

- 文件消息、图片消息右键「复制」：**Windows 上改为系统文件剪贴板格式（与在资源管理器里 Ctrl+C 一个文件等效）**——粘到任何文件夹出来的就是文件本身，提示文案改「已复制文件」。v2.5.1 的「复制到路径」在 Windows 上作废。
- macOS 暂维持现状；Linux 维持路径方式（文案保持诚实）。Windows 真机粘贴效果待复验（见文末清单）。

## 8. 设备 ID 改为机器绑定（连接码最后变一次，请注意）

- 此前设备 ID 是随机生成后存本地的，卸载重装或清数据就会变（v2.5.1 实测中连接码从 788 908 变 205 480 就是这个原因——已查实 v2.5.1 没有改动 ID 生成/存储代码，是卸载把数据清了）。
- 本版改为**按操作系统机器标识确定性派生**（Windows 读 MachineGuid、Linux 读 machine-id、macOS 读平台 UUID，做哈希后组装成设备 ID；原始机器标识只在本机参与计算，绝不外发；读不到时回退到随机生成并存本地，与旧行为一致）。
- **须知：装上本版后，连接码会变最后一次**（从随机 ID 切换为机器派生 ID），对方设备需用新码重连一次；**之后重装、清数据都不再变**。

## 9. 粘贴文件 + 多文件批量发送

- **输入框可直接粘贴文件**：在文件管理器里复制文件（单个或多选）后回聊天输入框 Ctrl+V，文件会挂到待发送区。剪贴板里是文件对象时文件优先，绝不会把文件路径当文字粘进去；没有文件对象时维持旧规则（文字优先、图片位图作图片、超长纯文字转长文文档等）。
- **多文件批量**：三个入口汇入同一条待发送队列——①附件按钮可选多个文件；②粘贴多个文件；③拖放多个文件（行为变更：拖放改为先进队列，不再拖入即直发）。发送前附件区可逐个移除、也可全部清空；点发送后按顺序逐个传（每个文件一条消息、各自进度），单个失败会提示并跳过、不堵住后面的。

## 10. 文件压缩升级为 zstd（注意互传版本要求）

- 可压缩文件的分片压缩由 zlib 换成 **zstd（3 级，速度/压缩率平衡）**，瓶颈在蓝牙空中带宽，压得更小就传得更快。实测同一个 6 MB 文本文件：空中字节 1,267,533 → 1,090,635（少约 13.9%），本机回环耗时约减半。已压缩格式（zip/图片/视频/pdf 等名单）仍跳过不压；压完反而变大的片段仍直传。
- **版本要求**：文本类等可压缩文件互传，**需双方同为 v2.5.2 及以上**。收到旧版压缩片段或不认识的算法时，本次传输会干净失败并给出明确提示（如「对方版本较旧，请升级后再传此类文件」），绝不写出坏文件（完整性仍由 SHA-256 校验兜底）。zip/图片等直传文件不受影响，新老版本可正常互传。

## 11. 文件发送收尾提速

- 此前进度到 100% 后还要干等：接收端要把整个文件重读一遍算校验和才回执，大文件就是数秒，进度条停在 100% 没任何文字，像卡住了。
- 本版：接收端收片时顺手增量计算校验和，收完直接比对（断点续传等不适用情形自动回退整文件重算，校验强度不降）；等待期间进度条显示诚实状态（发送方「已发送，等待对方校验…」、接收方「已收完，正在校验…」）；完成后的收起延迟也从约 0.9 秒降到约 0.4 秒。实测 300 MB 文件：改前校验约 16 秒且把会话误掐断，改后 100% → 进度条消失全程约 1.3 秒、会话不断。

## 12. AI 转发链故障修复（附真实接口实测）

- **查实一个旧 bug**：经对方设备转发提问（本机没配 AI、借对方的）此前必然失败，提示「对方未能提供 AI 代理」——原因是上游流式回答的第一片常常只有角色、内容为空，而转发通道把「空内容片段」误当成结束信号，第一片就断了，后面的真回答全被丢弃。本版双端修复：空片段不转发、不入等待通道。
- **真实 DeepSeek 密钥端到端实测（六步全过）**：设置页保存配置 + 测试连接成功；AI 页流式回答完整落屏；聊天框 @本机AI 回答以 AI 气泡落聊天；消息「问AI」带上下文出回答；转发链经对方设备拿到真实回答、对方转发统计 +1（数据库实查）；把模型名改成不存在的提问，报错提示为「接口返回异常（状态码 400）：请稍后重试」，能看懂、不卡死不崩。
- 注：实测在本机沙箱网络下进行，该网络的证书环境与正常网络不同，测试构建临时放宽了证书校验才连通；**正式构建的证书校验是严格的**（实测中已被拒绝不受信证书反证），正常网络下使用不受影响。

## 13. Windows 标题栏跟随应用主题

- 应用使用 Windows 原生标题栏，此前切到深色模式时标题栏仍是白色。本版把标题栏主题与应用主题同步：选深色标题栏变黑、选浅色变白、选「跟随系统」随系统深浅翻转（经后端命令调 Window::set_theme 实现）。本地只能验到调用接通与三平台构建，实际颜色待 Windows 真机复验（见文末清单）。
