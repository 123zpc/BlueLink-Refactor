# BlueLink v2.6.2（草稿测试包）

v2.6.1 真机验后清单 #1–#18 的修复轮，全轮以**传输速度与可靠性**为首：帧层与切片层双重加固（坏帧只丢帧不断连）、出站背压让发送进度恢复诚实、意外断线自动重连；外加一处安全定版（打开文件一律查看语义，脚本永不被「打开」执行）、TRAE 长历史必 422 的根因修复，以及图片气泡定稿、滚动策略定版等一批交互返工。

## 传输加固（本轮之首）

- **帧格式 v3：魔数 + CRC32 帧校验 + 流式重对齐**。帧头带 2 字节魔数（"BL"），帧尾带 CRC32 校验（覆盖类型+载荷）；接收端是带状态的流式解码器：失步时只丢损坏帧、扫描魔数重新对齐到下一帧头，**一帧损坏绝不杀死整条连接**。回归测试齐备：整帧丢失/帧内丢字节/整帧重复/单字节污染/前置垃圾/逐字节喂入，以及「在正常消息流中注入垃圾字节+篡改帧，随后消息必须在同一条连接上继续往来」——全过。注意：新旧版本帧格式不兼容（与 zstd 的既定口径一致），混版连接会握手超时干净失败，请两边都升级到 v2.6.2。
- **BLE/SimpleBLE 切片带序号**。每片盖递增序号：重复片在重组层即检出丢弃、丢片计数并落日志（载荷照常交付，受损帧由帧层 CRC 兜底重对齐）。旧版裸切片无序号，空中丢/重一片就字节流错位、读出天文数字帧长整条连接暴毙（v2.6.1 真机实锤：帧长度超限 153239697、图片首发校验失败）。四处入站喂流的「通道满就丢字节」（try_send）全部改为等待背压，静默丢字节绝迹。
- **出站有界队列 + 背压**。旧版无界队列把「已交给传输层」冒充「已发出」：42KB 的图还在空中慢慢滴灌，发送端已经报 100%，整段传输尾巴被误标成「等待校验」（#18 定案）。现在出站队列有界（8 帧），发送被真实发送节奏节速；界面状态严格区分「发送中」与「校验中」。
- **连接关闭的合法原因只剩两类**：传输层真 EOF、协议心跳判死。其余一律降级为消息级失败：坏帧丢弃重对齐、单文件解压/校验失败只判该文件失败并立即回执（旧版会让发送端永远等不到确认、传输挂死）、单条消息解码失败只丢该条。全量错误传播审计见 QA 记录。
- **经典蓝牙审计（#11）**：写泵加 30 秒发送超时——适配器假死/对端不读时阻塞 send 不再永久挂住（旧版关连接也唤不醒它）；收、发、心跳三路本就解耦（双阻塞线程泵 + 独立心跳任务），长流式期间心跳被饿死的路径已封。断开原因落字区分用户主动/链路结束/心跳判死/发送失败，并新增下条的自动重连分流。
- **意外断线自动重连**（派生自 #11）：非用户主动断开而中断时，自动按上次路线回拨对端，退避 2s→5s→10s→30s 封顶、总限时 180 秒停手并落字；重连期间界面顶部有「正在自动重连」横幅（可手动停止）；成功后按既定落点规则回到该对端会话；用户主动点断开绝不触发；握手沿用连接码校验。蓝牙路线带缓存旧端点兜底（清缓存按名重扫重试一次）。
- **速度口径（本机环回/模拟口径，真机待验）**：帧层加固后环回吞吐（与经典路径同一编解码）约 346 MB/s——加固前约 1.49 GB/s 是**毫无完整性校验**的裸奔数字；346 MB/s 仍是经典蓝牙 EDR 物理上限（约 0.25 MB/s）的千倍以上，空中速度不受影响。BLE 模拟泵（2ms/片串行模型）改前/改后同为约 64 KB/s（延迟主导，协议开销不改变串行模型）；无延迟串行约 65.5 MB/s。校验段：接收端增量哈希与收尾确认维持毫秒级（真机日志 0–11ms），慢的从来不是校验、是传输尾巴，现已由背压与状态区分根治；本轮局域网实测发送端「最后一片→收到确认」约 41–46ms、接收端哈希 0ms。
- **评审与审计**：本轮全量改动经独立第三方代码评审（DeepSeek）两轮，采纳修复 4 项（重连路线只许出站连接消费、AI 转发失败不残留等待者、删除会话的索引清理合并、打开分类补无扩展名文本兜底）；错误传播全量审计另补强 2 处——接收写盘/收尾落盘失败也统一判该文件失败并立即回执，不让发送端干等。

## 安全（#9）：「打开文件」一律查看语义

v2.6.1 实锤：超过 10MB 的 .py 点「打开」被系统默认 verb 直接执行。现按扩展名三类处置，任何路径下都不会点一下就把脚本/程序跑起来：

| 类别 | 扩展名 | 处置 |
|---|---|---|
| 文本/代码/脚本 | txt log md rs py js ts java c cpp h cs go rb pl php lua sh bash zsh bat cmd ps1 psm1 vbs sql json toml yaml xml html css vue ini cfg conf csv 等 | 内置查看器只读打开（任意大小；>10MB 降级模式：关高亮+虚拟渲染；>100MB 只在文件夹中定位并明示） |
| 二进制可执行 | exe msi com scr cpl dll sys jar apk dmg pkg deb rpm appimage run bin lnk url 等 | 只在文件夹中显示，永不系统打开 |
| 其余文档/媒体 | pdf、Office 文档、图片、音视频、压缩包等 | 系统默认程序打开（查看语义成立的格式） |

## 网关（#13）：TRAE 长历史必 422 根因修复

真 DeepSeek 接口二分复现定案：纯长历史（200 条、乃至 56 万 token）全部 200，**被拒的只是消息形态**——assistant 消息 content=null 且无 tool_calls、tool 消息失去前置 tool_calls，各必 400（经 TRAE 表现为 422）。而本应用的网关恰恰在转发时把消息压平成 (role, 纯文本)，tool_calls 被丢弃——长历史里只要有一组工具调用就全盘失败。现在：本地 API 与转发全程走富消息（content 原样、tool_calls/tool_call_id 完整保留），在真正调用上游的一侧统一规范化（null 补空串、孤儿 tool 降级为 user、分段数组压平为文本、规范 tool 配对原样保留）；上游错误原文（截断脱敏）落运行日志，不再只剩状态码。验收：143 条 TRAE 形态历史（含上述全部残缺形态）经网关→蓝牙转发→上游得 200 并有回答（上游以与真接口同规则的校验替身验证；真接口的形态规则已由二分实测逐项坐实）。

## 图片与渲染（#1/#14）

- **图片气泡定稿**：气泡即图片本体——透明底、零内边距、圆角 18、按原宽高比定尺寸（最大 320），照片直接落在聊天背景上，只留轻阴影+1px 细描边，发送端不再有蓝板、接收端不再有白卡。
- **图片组**：封面端正，身后两层用**其他照片的真实缩略图**，向右上错开约 10px 并带 −5°/−2.5° 轻微旋转（卡牌叠放感），「共 N 张」深色半透明胶囊浮封面右下角。
- **状态呈现**：发送中/校验中一律用贴下沿 4px 进度细条 + 图角小胶囊，任何状态（包括校验中）都不撑高气泡；图片消息上下间距明显收紧。
- **失败态**：未验内容不出预览；失败时只给紧凑卡（文件名+校验失败+重试）；成功图片双端同形态（只图片本体、无文件卡行），文件名进查看器看。

## 入口与导航（#2）

冷启动默认停在**连接页**（不恢复上次页面）；未连接看历史的唯一入口是既有会话列表（默认收起、悬浮按钮展开）；不再出现名为「未连接」的占位会话；进历史时顶栏对方名+灰点未连接、底部提示带「当前未连接，只能查看记录」+「去连接」（原有形态保留）；连上谁落谁的会话；导航互切不丢正在看的会话与浏览位置。

## AI 会话与回复（#3/#4/#5/#7/#10）

- **#3 会话条**：胶囊右键菜单明确有「重命名」「删除」（删除两步确认；删当前打开的回落「AI 助手」；「AI 助手」本身不可删；连同消息一并清除、重启不复活）；双击改名保留且不再被切换重渲染打断；横向滚动条隐藏、悬停才显极细条；胶囊可拖拽左右排序、顺序持久化。
- **#4 思考胶囊对齐**：AI 输入行单行时「思考」胶囊与输入框严格居中对齐；输入长高时胶囊与发送键同排底对齐（与聊天输入框同一逻辑）。
- **#5 等待占位锚定**：@AI 的「正在等待…」占位按所答问题锚定、紧随问题气泡之后，任何刷新重排不移位（此前占位会跑到问题上方甚至越过日期分隔线）；AI 页同查。
- **#7 代码块高亮**：AI 回复的代码块按围栏语言走查看器同一套 tokenizer 高亮（浅/深同主题）；流式中已闭合的块即时高亮、生成中的块收尾后补高亮，不拖卡流式。
- **#10 回复收起**：AI 回复新增「收起」动作（与收藏/置顶同列），折成收缩条（首行摘要+展开入口），状态按消息持久化、重启不丢，AI 页与聊天 @AI 气泡两处生效。

## 滚动定版（#6/#15，用户亲自收口）

贴底时：接收、发送新消息与 AI 流式都自然跟随贴底；用户**手势**（滚轮/触摸/拖滚动条/键盘）一出立即停跟随——不设阈值、不靠位置猜，停跟随期间新内容只往下长、scrollTop 分毫不动；恢复跟随只由自滚回底、点「回到最新」、本人发送三条路径触发。此前「离底守卫误伤发送路径、发送后不回底部」一并根治。聊天与 AI 页同规。

## 其余（#8/#12/#16/#17）

- **#8 万行粘贴不再冻死**：粘贴检测只扫前 300 行定性（结论不变）、检测防抖合并、超长输入跳过整篇高度测量；发送点击永远有响应。回归口径：约 1 万行/1MB 粘贴不卡、能发（rig 实测见 QA）。
- **#12 连接步骤卡响应式**：窄宽（≤1080px）时连接页改单列纵排，步骤卡占满整行、不再挤在侧栏里；宽屏两栏布局不变。
- **#16 待发队列限高**：队列区限高约两行封顶，chip 紧凑横向流式排列、超出区内滚动；计数、合并开关与「清空」钉在首行不随滚动消失。
- **#17 队列追加可靠**：选择器防重入（叠开会吞结果）；选了文件却一个都没新增时明示原因（多半是已在队列中），不再静默；三入口（选择器/粘贴/拖放）混合追加回归通过。

## 兼容性

- 帧格式 v3 与旧版不互通：两边都升级到 v2.6.2 再连接（混版握手超时干净失败，与 zstd 口径一致）。
- 本包仍为草稿测试包，正式版 Latest 不变。
