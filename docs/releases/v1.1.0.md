# v1.1.0 客户交付版（优化循环）

> 循环第 4 圈 ｜ 日期：2026-11-18 凌晨 ｜ 性质：**交付客户版** — 在 v1.0.0 基础上做客户反馈功能与性能优化

## 甲方需求（客户代表，来自 v1.0.0 复盘回流池）

- 找东西更快：全局命令面板、聊天内日期锚点。
- 聊天记录能带走：会话导出。
- 传输进度要准：多文件并发时进度条不能串到别的文件上。
- 性能要有数：给出与需求预算对照的实测数据。

## 乙方交付

- **Ctrl+K 命令面板**：视图跳转、断开、导出、全部标签直达抽屉；支持过滤、方向键选择、回车执行、Esc 关闭。
- **日期锚点栏**：聊天视图右侧列出会话出现过的日期，点击平滑滚到当天第一条（与已有日期分隔线互补，不新增第二套定位机制——仍走消息行定位）。
- **会话导出**：聊天页「导出」按钮，把当前会话导出为 Markdown 文件（保存对话框选路径，新增 save_text_file 命令落盘）。
- **传输进度精确归属**：服务层 TransferProgress 事件新增 msg_id，界面按消息 ID 精确命中对应气泡的进度条（并发多文件不再串扰）；找不到时回退到最近文件气泡。
- **性能基线测试**：存储层新增 1 万条消息的性能测试，进入常规测试套件长期守门。

## 测试报告（测试组）

- 全量自动化测试 16 个全过（新增性能基线 1 个）。
- **性能实测（1 万条消息，本机）**：分页加载 200 条 **1.13ms**；全文搜索 **0.95ms**（命中 100 条）；按标签列取 **6.87ms**（100 条）。三项均远低于需求 N 类预算 500ms，余量约两个数量级。
- **与原版基线对比**：原版文件传输整包内存加载、无分片无续传，且 send() 部分发送不检查、单次 read 假设读满（实测代码审查结论）；新版 256KiB 流式分片 + 区间续传 + 全文件 SHA-256 校验，2MB 文件实测传输后 MD5 一致，预置 1MiB 的断点续传用例通过。

## 客户验收（客户代表 + 用户研究组）

- 验收结论：**通过，发布 v1.1.0**。四项客户反馈全部落地，性能数据达标且有自动化守门。
- 保留项：蓝牙通道仍为最高优先级欠账（见已知问题）；AI 回复多版本切换继续留在需求池。

## 已知问题

- 连接通道仍为局域网 TCP，蓝牙双通道后端未接入（下一主线）。
- Windows/macOS 安装包由 CI 验证编译，分发包与签名未做。
- GUI 键鼠全流程自动化在虚拟显示下不可靠，真机点按验证待 UAT 补做（v1.0.0 保留项延续）。

## 复盘回流（进入下一圈需求池）

- [最高] 蓝牙双通道后端（BLE 发现/信令 + 平台高速通道）。
- AI 回复多版本切换；消息多选批量操作（标签/导出所选）。
- 三平台安装包产出与签名；真机 UAT 记录补齐。
