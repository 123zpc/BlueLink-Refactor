# v1.1.1 补丁版（缺陷修复 + 打包通道）

> 循环第 5 圈 ｜ 日期：2026-11-18 凌晨 ｜ 性质：**交付客户版（补丁）** — 修复 v1.0.0/v1.1.0 的 Windows 构建失败，补齐安装包产出

## 缺陷来源（客户验收环节发现）

发起人查 CI 通知时发现问题，项目组跟进 GitHub Actions 日志定位：

- v1.0.0 与 v1.1.0 两次运行的 **windows-latest 作业都失败**，卡在「Clippy」步——实际不是代码警告，而是编译桌面应用时 Tauri 构建脚本报错：`app/icons/icon.ico not found; required for generating a Windows Resource file during tauri-build`。
- 根因：图标只做了 PNG（32/128/256），**漏了 Windows 必需的 .ico 与 macOS 打包用的 .icns**。Linux 本地构建不需要 .ico，所以本地全绿没暴露；这也说明三平台 CI 的价值——它抓住了本地抓不住的问题。
- 顺带澄清同批被关注的 macOS「Cancelled」：v0.2.0 那次是 GitHub 的 macOS arm64 运行器容量不足、作业排队 15 分钟未获机器被系统取消（日志原文：`The job was not acquired by Runner of type hosted even after multiple attempts`），与代码无关；v1.0.0 那次 macOS 实际成功（3 分 1 秒）。

## 修复内容

- 新增 `app/icons/icon.ico`（内嵌 16/24/32/48/64/128/256 七个尺寸）与 `app/icons/icon.icns`（128/256/512/1024），与现有 PNG 同一图稿（蓝底白环）。
- `tauri.conf.json` 的 bundle.icon 补齐五件套。
- 新增发布工作流 `.github/workflows/release.yml`：打 v* 标签时在 Ubuntu/Windows/macOS 三台机器上分别打包，安装包自动挂到对应 GitHub Release（草稿）——从此每个版本都有可下载、可安装的包，不再只有裸二进制。

## 验证结果（2026-11-18 凌晨，全部通过）

- **CI（提交 173f891）**：整体 Success — ubuntu 3 分 23 秒、**windows 4 分 54 秒（转绿，icon.ico 修复确认有效）**、macos 3 分 37 秒（这次拿到了运行器，未被取消）。三平台全绿达成。
- **发布工作流（标签 v1.1.1）**：三个打包作业全部成功，Release「BlueLink v1.1.1」含 7 个安装包：Linux 的 .deb / .AppImage / .rpm、Windows 的 .msi / -setup.exe、macOS（Apple Silicon）的 .dmg / .app.tar.gz。
- **本地安装运行（Linux）**：本地同源打出 BlueLink_1.1.1_amd64.deb（5.75MiB），dpkg 安装成功（包名 blue-link 1.1.1），从 /usr/bin/bluelink-app 启动安装后的程序，连接页正常渲染、连接码正常生成、数据库与设备 ID 正常落盘 — 「打包→安装→运行」闭环成立。
- 保留项：Windows/macOS 安装包在真机上的安装运行仍需发起人在真机完成（UAT）；安装包未做代码签名，Windows SmartScreen/macOS Gatekeeper 首次运行会提示未签名，属已知事项。
