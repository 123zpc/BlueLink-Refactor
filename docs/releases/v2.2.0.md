# BlueLink v2.2.0 发布说明（按验收原型落代码）

发布日期：2026-11-18 ｜ 类型：客户交付版（功能迭代）

本版内容即 2026-11-18 用户点验通过的 Figma 原型（44 个画板）的落地实现。

## 本版内容

- **彩签改为「颜色即分类」**：9 种颜色就是 9 个分类，每个颜色可改名（如红色叫「文件」），给消息选颜色即归类，一条消息只归一类；改名后全类同步。消息下显示分类小片（备注优先、否则分类名）；聊天页右上彩签条悬停弹出该类全部条目，点条目定位并闪烁原消息；彩签总览页按分类查看。旧版标签数据自动迁移：按颜色并入对应分类（同色合并），已打开过的库首次启动自动完成。
- **引用回复**：消息可引用回复，气泡上方带原消息引用块；点引用块跳回原消息，并出现「回到回复」按钮可跳回。
- **AI 配置补全**：设置里可调温度、最大回复长度、系统提示词、流式开关；测试连接显示延迟。系统提示词由真正调用接口的一侧自动附加。
- **AI 代理网关（本版重点）**：A 电脑没网、B 电脑有网且配了 AI 时——
  - A 在 AI 页直接提问，经蓝牙由 B 转发到 B 配置的 AI 回答（现在也是流式逐字返回）；
  - A 还可在本机开放 OpenAI 兼容接口 `http://127.0.0.1:8321/v1`（含流式），供 A 上的其他软件填这个地址调用，同样经 B 转发；只监听本机回环地址、不对外，可另设本机访问密钥；
  - 上游密钥只存在 B 上，永不过蓝牙；B 端「AI 转发」许可默认关闭，须在 B 的设置里手动打开才会被借用，并统计今日已转发次数与用量；未开启时 A 侧收到明确提示，不会假死。
- **文件传输补全**：传输进度显示百分比与已传/总大小，传输中可取消（双方收敛），失败/取消/校验失败有明确状态且可重试；发送失败的文本可点状态重发。点文件卡弹出菜单：打开、打开文件位置、复制文件、另存为、删除记录。
- **粘贴规则修正**（按用户裁定）：剪贴板里有文字时永远优先文字——从 Excel 复制粘贴进来就是文字，不再变成图片、也不转 CSV；超长才转「长文.txt」；代码仍按语言转文档；只有剪贴板里根本没有文字（纯截图）时才按图片附件发送（输入框上方有附件条，可移除）。
- **设置新增存储分区**：显示聊天记录/接收文件/缓存占用，可清理缓存、可清空全部聊天记录（二次确认）。原「标签」入口更名为「彩签」。

## 蓝牙速度说明（如实记录）

同 v2.1.0：未做极限调优，无真机吞吐数据；局域网通道下 40 MB 文件传输在十几秒量级完成（未精确计时，且该通道不是蓝牙）。蓝牙实际速度以真机验收为准。

## 验证状态（如实记录）

- 自动化：全工作区 20 个单元/集成测试全过（含彩签分类全流程、老标签迁移、AI 代理许可门槛与统计、网关流式），clippy 零警告，fmt 通过；GitHub CI 三平台与 Release 构建以本版发布时结果为准。
- 本机 GUI 实测（开发者模式局域网通道 + 命令行节点 + 本地模拟 AI 上游）：连接与双向聊天、彩签归类（选红色）与消息小片、彩签条悬停列表、引用回复与引用块、40 MB 文件接收进度（百分比/大小/取消按钮）与完成校验（MD5 一致）、文件菜单、AI 页经对端转发问答、设置各新分区与开关落库，均走查通过（截图存档）。
- 网关端到端实测：对运行中应用的 `127.0.0.1:8321` 发起非流式与流式（SSE）请求，均经对端节点转发到模拟上游并正确返回；B 端统计记为 2 次调用。
- GUI 实测中发现并修复一个严重缺陷：开启本地 API 后重启应用会因启动阶段无 Tokio 上下文而崩溃（开启后每次启动必崩）；已改为经 Tauri 运行时启动，并复测「开启状态下冷启动 + 接口可用」通过。
- **未验证项**：粘贴图片附件的完整发送链路（Xvfb 下剪贴板注入不可靠，仅代码走查 + 落盘命令实测）；彩签改名浮层、传输中途取消的界面操作未在 GUI 逐项点测（后端与存储层有自动化测试覆盖）；两台真实设备间的蓝牙配对、聊天与文件传输仍需用户真机验收（开发机无蓝牙硬件）。
- 已知限制：安装包未签名，Windows SmartScreen / macOS Gatekeeper 首次运行会提示。
