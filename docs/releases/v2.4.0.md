# BlueLink v2.4.0（测试版，未正式发布）

本版两件大事：**连接页换成定版原型的桌面两栏新界面**，并**并入 v2.3.1 的全部修复**（那个包未单独真机测试，按用户安排在本包一次测完）。仍为**测试版**：经典蓝牙的配对、连接、传输速度等运行时行为待真机确认后再走正式发版。

## 新连接页（两栏桌面布局）

- 左栏：设备列表面板（标题+台数+扫描/停止按钮，列表在面板内独立滚动，设备再多也不会把页面顶出去）；设备行含蓝牙图标、设备名、副行「传输方式 · 已配对」、上次连接徽标、信号格（有 RSSI 才画，经典扫描没有就不画）、连接按钮。
- 右栏：信息卡列——本机设备（大号连接码）、上次连接（一键重连/清除）、连接状态（各传输人话文案，异常带说明）、连接步骤（没有上次连接记录时是详细指南版）；点设备后第一张卡换成输码面板，对应设备行描边高亮。
- 十个状态齐全：浏览、输入连接码、扫描中（骨架行）、空结果、异常（服务启动失败橙色提示+人话说明）、连接中（按钮转圈禁用）、连接失败（红描边+红字）、已连接、开发者模式、无上次连接。
- **右栏滚动条规矩（本版按用户新要求调整）**：默认正常状态下右栏不出现滚动条——各卡片已按默认窗口尺寸收紧，浏览/输码/异常等常态都完整塞下、步骤卡的提示行钉在卡底完整可见；滚动条只在内容真的变多时才出现（窗口拉矮、开发者模式多一张卡等），是自适应兜底。
- 开发者模式（设置页连点版本号三次开启）：右栏多一张开发者卡，含经典蓝牙 / BLE / SimpleBLE 三段切换与局域网测试入口；该状态卡片总高超出右栏，保留栏内滚动。

## 并入的 v2.3.1 修复（本包一并真机验）

1. **单实例防双开**：应用已在托盘运行时再次点图标，只唤出已有窗口，不再启动第二个进程（双开是经典蓝牙服务端口被占 WSA 10048 的常见来源）。
2. **10048 人话提示**：端口仍被占用（如老版本在运行）时，状态卡显示「经典蓝牙：服务启动失败」并附说明「端口被其他程序占用（多半是另一个 BlueLink 或老版本正在运行），关掉它再重启本应用；你主动连接别人不受影响」；原始错误完整保留在运行日志中。
3. **小图标加粗**：`.ico` 的 16/20/24/32 小帧笔画适度加粗（48+ 帧未动），任务栏小图标更易辨认。提醒：若装后仍显示旧的「蓝方块+白圆环」，那是 Windows 图标缓存残留（旧版图标），重启资源管理器或重启系统即刷新，与安装包无关。
4. **Windows 安装包带 SimpleBLE**：开发者模式的传输切换中可选择 SimpleBLE（流水线有校验步保证已编入）；Linux/macOS 包未启用，选了会如实提示并回落经典蓝牙。注意：在开发者模式切换到 SimpleBLE 后需重启应用，本机才会被对方经 SimpleBLE 发现（主动扫描/连接立即生效）。
5. **运行日志入口**：设置 → 存储 → 「运行日志」一行有日志目录路径与「打开目录」按钮；日志文件为数据目录下 `logs/bluelink-YYYY-MM-DD.log`，按天滚动。

## SCANPROBE 扫描诊断（请协助回传一次日志）

为定案「经典蓝牙到底能不能拿到信号强度」，本包延续 v2.3.1 内置的日志级探针（仅写日志，不动界面、不改扫描结果）：扫描时把三套接口能拿到的全部字段写进运行日志——经典 Inquiry 原始结构全字段、WinRT DeviceWatcher 申请的 13 项 AEP 属性逐项记录（重点 SignalStrength，有值记值、没有明确标「（空）」）、BLE 广播全字段。

**操作方法**：装好本包 → 在连接页点一次「扫描」（经典蓝牙模式），等设备列表出齐 → 设置 → 存储 → 运行日志 → 「打开目录」→ 把当天的 `bluelink-YYYY-MM-DD.log` 发回。日志里搜 **SCANPROBE** 即是探针段；据此可定案经典设备行要不要显示信号格（现结论仍是：官方接口层面经典 Inquiry 无 RSSI 字段、连接后也无官方读法，故经典行暂不显示信号格、不造假数据；BLE 行照常按 RSSI 显示格数）。
