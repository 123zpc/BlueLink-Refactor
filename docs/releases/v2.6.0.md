# BlueLink v2.6.0（测试版，未正式发布）

本版主题是**内置查看器**：聊天里收到的文本/代码文件、图片、音视频，不用再跳系统程序，直接在应用里点开看；外加一个新消息形态——**图片组**：一次发多张图可以合并成一张堆叠卡片，对方收到也是合并的。再顺手修掉两个老毛病：**文件消息状态文案卡在「发送中」**、**图片组进度条可能卡在「正在校验…」**。仍为**测试版**，正式发版的一次机会未动用。

## 1. 文本 / 代码查看器（只读）

- 聊天里的文本类文件（.txt/.md/.json/.log 与各类代码文件等）和「长文.txt」，点击直接在应用内打开，不再依赖系统程序。
- 功能：**行号**、常见语言**语法高亮**、**UTF-8 / GBK 编码自动识别**、**文件内查找**（Ctrl+F，命中跳转并高亮）、**可选中复制**（鼠标拖选、双击选词、Ctrl+A 全选、Ctrl+C 复制）。
- **秒开**：点击先出原文第一屏，高亮随后补上，不转圈等排版；30,000 行、约 1.3 MB 的代码文件本地实测点击即开、拖到底部行号高亮都对得上。
- **大文件不卡**：只渲染看得见的行；选中和复制按全文计算——只渲染几十行时 Ctrl+A + Ctrl+C 也能完整复制全文（实测 1,327,229 字节与源文件逐字节一致）。
- **上限**：超过约 10 MB 的文本不硬撑，提示后改用系统程序打开。
- 查看器是**页内全屏层**，不是新窗口：没有第二个窗口的启动开销，点开即出、关掉即释放内存。

## 2. 格式化快捷处理（查看器内，原文不动）

- 工具栏一键处理：**JSON 美化 / JSON 压缩、XML 美化、代码整理缩进、Base64 编码 / 解码、URL 编码 / 解码、时间戳转换**（10 位秒 / 13 位毫秒自动识别，优先取选中内容里的数字）。
- 都是**显示层处理**：横幅会明示「原文未修改」，处理结果可一键复制，也可一键回到原文。原文件一个字节都不动。

## 3. 图片查看器

- 图片消息与图片文件点击在应用内打开：**适屏显示、滚轮缩放、拖动平移、左右旋转、双击在适屏与 1:1 之间切换**。
- 从图片组点开时可直接用左右箭头（或键盘方向键）在组内翻看整组。

## 4. 音视频

- 音视频文件点击走内置播放（系统 WebView 自带能力，能播就行，不做播放器功能）；实在播不了的格式会明示并给出「用系统程序打开」。
- PDF 与 Office 文档本版仍走系统程序打开，不变。

## 5. 图片组（新功能）

- **合并发送**：一次选/粘/拖超过 3 张图片时，附件栏出现「合并为一组发送」开关，**默认开启**，发送前可关掉改回逐张发。
- **堆叠卡片气泡**：合并后聊天里只占一个气泡——仿手机短信的卡片堆叠样式，带「共 N 张」标识、露出底层卡片边缘，气泡上可左右翻卡，点开进图片查看器大图翻看整组。
- **保存全部图片**：右键组气泡有「保存全部图片…」，选一个文件夹后按发送顺序存为 1、2、3…（各保留原扩展名）；中间有文件已不在原位置时跳过它且不补号错位。
- 合并是**消息本身的属性**：对方收到也是一个合并气泡，不会散成一堆单图。

## 6. 兼容与降级（对老版本）

- **老版本（v2.5.2 及更早）收到图片组**：实测（v2.5.2 构建与本版双向联调）——老版本会把组里的每张图当作**独立的图片文件消息**逐张接收、逐张校验完整，不崩、不写坏数据；只是没有合并展示。老版本发给新版本的文件、图片也一切正常。
- 本版内部：图片组走既有文件传输通道逐张传，每张都带组标记；老版本不认这个标记就当普通文件收，所以能干净降级。

## 7. 顺手修复

- **文件消息状态文案卡「发送中」**（v2.5.2 就存在的老缺口）：文件明明传完了，气泡下还一直写「发送中」。根因是文件发送收尾只报了传输状态、没报消息状态。本版补齐，与文字消息口径一致；实测新发文件文案当场变「已送达」，不用重启。
- **图片组进度条竞态**：图片太小、传得太快时，成员完成事件可能赶在气泡画好之前到达被丢掉，进度条会永远停在「正在校验…」。本版以组消息自身状态做最终对账收尾，实测连发小组不再卡住。

## 8. 性能与体积

- 查看器全部手写实现，没有引入 Monaco 一类 MB 级框架；**零新增第三方依赖**（GBK 解码用系统自带能力、图片走系统资源协议）。
- 体积增量实测（同机、同 release 配置、UI 资源内嵌于二进制，Linux x86_64）：v2.5.2 为 35,714,592 字节，v2.6.0 为 36,092,608 字节，**增量 +378,016 字节（约 369 KB）**，在「几百 KB 级」红线内。

## 未验证清单（如实）

- Windows / macOS 真机：查看器与媒体播放在真实桌面（WebView2 / WKWebView）的表现、图片组经真实蓝牙链路发送、气泡上翻卡的真机点测、「保存全部图片」的文件夹选择全流程——本地无头环境验不了的部分都列在这里，等真机复验。
- 本地无头环境缺 H.264 解码插件与音频服务，音视频只验到「查看器打开 + 播不了时给系统打开兜底」；实际解码依赖各系统 WebView 的原生能力。
- 大文件（几千行以上）的高亮按可视区分片补算，分片边界处的跨行注释/字符串着色是近似处理，个别行颜色可能与全量计算略有出入（只影响颜色，不影响内容与复制）。
- 经典蓝牙连接后传文件速度仍未真机实测（正式发版前必须完成，与前几版同一条）。
