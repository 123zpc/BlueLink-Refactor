# 技术选型与产品标准

> 2026-11-17 定。所有代码注释一律中文（见第三节），本文档即按此执行。

## 一、语言选型：Rust（不用 Java）

结论先行：**新版本用 Rust 重写，放弃 Java。** 理由是实测过的生态现状，不是偏好：

| 维度 | Java | Rust |
|---|---|---|
| 跨平台蓝牙 | 蓝牙栈生态基本死亡：JSR-82 / BlueCove 多年前已停止维护、不支持现代 macOS；原版被迫用 JNA 手写 Winsock 调用，这正是它只能跑 Windows 的根本原因 | `btleplug` 是活跃维护的跨平台 BLE 库，一套 API 覆盖 Windows（WinRT）、macOS（CoreBluetooth）、Linux（BlueZ）；Linux 另有官方 `bluer`（BlueZ 官方 Rust 绑定，含 RFCOMM），Windows 另有微软官方 `windows` 绑定可用 RFCOMM |
| 三端支持 | 桌面端要拖 JVM 运行时，蓝牙层每平台都要重新手写原生桥 | 单个原生二进制，三平台同一套传输接口 |
| 稳定性（少 BUG） | 空指针、并发问题全靠运行时与自律 | 所有权与借用检查在编译期消灭整类内存与数据竞争问题；`clippy` 全量警告即错误 |
| 体积与启动 | 原版拖 Spring Boot 后安装包与启动成本失控（见重构方案实测） | 无运行时，安装包可控在十几 MB 量级，冷启动快 |
| UI | Swing 观感陈旧，是原版"像玩具"的主因之一 | Tauri 2 用系统 WebView 渲染现代界面，后端仍是 Rust 原生 |

代价（写明，不藏）：Rust 学习与开发速度前期慢于 Java；macOS 上经典蓝牙 RFCOMM 无论哪个语言都没有好用的现成库 — 应对见第二节双通道设计。

## 二、传输设计：双通道，效率优先

- **控制与聊天通道（BLE）**：基于 `btleplug` 三平台统一实现，负责设备发现、配对码、聊天消息、AI 流式片段与传输控制信令。
- **文件高速通道**：协议从第一天就设计成与底层无关的分片协议，文件传输优先走平台高速后端（Windows / Linux 用 RFCOMM，吞吐高于 BLE）；macOS 无可用 RFCOMM 时回落到 BLE 分片通道，功能不缺席。
- **效率手段（全部写进协议，不靠调参碰运气）**：
  - 流式分片：固定分片边读边发边落盘，内存占用恒定，文件大小无上限，支持断点续传；
  - 协商最大 MTU、流水线发送（不等逐包确认）、按分片校验（只重传坏分片）；
  - 选择性压缩：先嗅探文件类型，已压缩格式（图片、视频、zip 等）直接原样传，只对文本类启用 zstd；
  - 全程零热路径日志（分级日志默认关闭调试输出）。

## 三、代码规范

- **注释全部中文**：`//`、`///` 文档注释、模块说明、待办标注，一律中文；代码标识符保持英文（行业惯例，利于查文档），日志与界面文案中文优先。
- `rustfmt` 统一格式；`clippy` 警告即错误，不留警告合入。
- 生产代码禁止随手 `unwrap()` / `panic!`，错误必须显式处理并给用户可读的中文提示。
- 每个模块先有单元测试再合入；协议编解码做模糊测试；提供虚拟传输回环，三端 CI（Windows / macOS / Linux）全绿才算完成。

## 四、界面标准：不像玩具，更不像"AI 生成的模板"

- 定位：成熟桌面通讯软件的观感，参照 Telegram Desktop、微信桌面版这类正式产品的克制设计，而不是演示 Demo。
- 禁区（原版与常见 AI 模板的通病）：紫蓝渐变、玻璃拟态、大圆角卡片堆叠、满屏 emoji 图标、阴影泛滥、留白失衡 — 一律不用。
- 用系统字体与平台原生窗口控件，三平台各自符合本平台习惯（标题栏、菜单、快捷键）；深色模式跟随系统。
- 布局：左侧会话/设备列表 + 右侧聊天区的主从结构，信息密度向正式 IM 看齐；动效只用在状态过渡，不做装饰动画。
- 设计先行：先出设计稿与组件规范（颜色、字号、间距成体系），再写界面代码；每个界面都要过"拿掉 Logo 还认得出是成品软件"这一关。

## 五、AI 对话标准：对标官方客户端体验

- 流式输出逐字渲染，滚动跟随可打断；支持随时停止生成、重新生成、编辑重发。
- Markdown 与代码块完整渲染（语法高亮、一键复制），长回复不卡界面。
- 会话管理：多会话列表、重命名、删除、上下文多轮记忆，全部本地存储。
- 延续原版核心思想：有网的电脑做 AI 代理，无网的电脑通过蓝牙向它发起 AI 请求，流式片段经蓝牙回传 — 这是本产品区别于普通 AI 客户端的特色，必须保留并做好。
- 接口走 OpenAI 兼容协议，用户自填地址、密钥与模型；密钥只存本地，界面内可配置、可测试连接。
- 异常体验：断网、超时、密钥错误都要有明确中文提示与重试入口，不许静默失败或转圈到底。
