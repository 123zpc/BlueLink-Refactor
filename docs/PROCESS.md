# 开发流程

> 模仿大厂规范流程：文档先行、评审把关、阶段确认。每道关口由项目发起人（用户）确认后才进入下一阶段，不抢跑、不跳步。

## 阶段与关口

| 阶段 | 产出物 | 关口（确认后才继续） |
|---|---|---|
| 0. 立项 | 重构章程、选型结论（DECISIONS.md） | ✅ 已确认（2026-11-17） |
| 1. 需求 | PRD.md（功能清单、范围、不做清单） | ⏳ 本次提交评审 |
| 2. 架构 | ARCHITECTURE.md（分层、工作区、数据模型概要） | ⏳ 本次提交评审 |
| 3. 交互与视觉设计 | 设计规范（颜色/字号/间距）、关键页面设计稿 | 待 PRD 与架构确认后启动 |
| 4. 详细设计 | 协议 v2 规范、数据库表结构、IPC 接口清单、错误码表 | 待设计稿确认后启动 |
| 5. 开发 | 按模块迭代：协议 → 传输 → 服务 → 界面 → AI；每模块自带单测 | 每模块完成即汇报实测结果 |
| 6. 测试 | 三平台功能测试、传输压力测试（大文件/弱连接）、长会话性能测试 | 测试报告评审 |
| 7. 发布 | 预览版 → 正式版；版本号与标签对齐；发布说明 | 发起人确认后发布 |

## 贯穿全程的规范

- **文档即仓库资产**：所有设计文档进 `docs/` 并版本化，改设计先改文档、过评审，再改代码。
- **代码评审**：每次提交说明"改了什么、为什么、怎么验证的"；注释全中文（见 DECISIONS.md）。
- **CI 门禁**：三平台构建 + 单元测试 + clippy 全绿才合入；红灯不合入，无例外。
- **可验证汇报**：阶段汇报必须带实测数据（构建结果、测试结果、性能数字、截图），不报"应该没问题"。
- **原仓库红线**：123zpc/BlueLink 全程只读，不做任何修改。
