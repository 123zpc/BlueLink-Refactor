# 开发流程

> 模仿大厂规范流程：文档先行、评审把关、阶段确认。每道关口由项目发起人（用户）确认后才进入下一阶段，不抢跑、不跳步。

## 组织：按公司建制运作（v2，含客户与使用者）

本项目按一家公司的建制推进，并且**公司之外还有客户与使用者两个独立视角**，三方关系先理清：

- **客户（甲方视角）**：提出业务目标与价值标准的一方 — 关心"这东西做出来有没有用、值不值、范围与优先级怎么取舍"，负责**客户验收**。在本项目中由我方设客户代表岗独立扮演，在每道关口先于发起人确认进行客户侧评审，专挑"做了但没用、优先级排错、范围失控"这类问题；发起人（用户）是客户侧的最终拍板人。
- **使用者（终端用户视角）**：真正每天用这个软件的人 — 关心"好不好用、顺不顺手、出问题能不能自己解决"。由用户研究组以**用户画像**（见 PRD 第二节）代言，在需求、设计、测试三个阶段做场景走查与可用性评审；使用者不关心实现，只对体验有一票否决的建议权（记录在案，由产品负责人裁决）。
- **公司（乙方/交付方）**：下列各组负责把东西按标准做出来。

发起人（用户）担任**产品负责人 / 最终验收人**：只做方向与关口确认，不陷入实现细节。各组产出一律先经本组自查、再经相关组评审、再过客户代表与使用者代表两道视角评审、最后交发起人确认。

| 组 | 职责 | 主要产出 | 对谁负责交接 |
|---|---|---|---|
| 需求组 | 需求调研、需求规格、验收标准、变更管理 | PRD、REQUIREMENTS.md（详细需求规格）、变更记录 | 产出交设计组与开发组；验收标准交测试组写用例 |
| 产品/项目组 | 排期、阶段关口、跨组协调、风险登记 | PROCESS.md、阶段计划、汇报 | 对发起人汇报每道关口 |
| 架构组 | 分层架构、技术选型、详细设计（协议/数据/接口） | ARCHITECTURE.md、DECISIONS.md、详细设计文档 | 产出交开发组实现、测试组做性能验证 |
| 设计组（交互） | 信息架构、交互流程、页面结构与状态定义 | 交互稿、页面与状态清单 | 交 UI 组做视觉、开发组做前端结构 |
| UI 组（视觉） | 设计规范（颜色/字号/间距/组件）、视觉稿、图标 | 设计规范、关键页面视觉稿 | 交开发组还原；还原度由 UI 组走查验收 |
| 开发组 | 按详细设计实现、自测、代码评审 | 代码、单元测试、构建产物 | 交测试组提测；遵守注释全中文与 CI 门禁 |
| 测试组 | 按验收标准写用例、功能/性能/三平台测试、缺陷管理 | 测试用例（编号与需求对应）、测试报告、缺陷单 | 缺陷回开发组修复；测试报告交发起人评审 |
| 运维/发布组 | 打包、签名、发布说明、版本管理 | 三平台安装包、发布记录 | 经发起人确认后发布 |
| 用户研究组（使用者代言） | 维护用户画像、典型场景库；做可用性走查与用户验收测试（UAT）组织 | 用户画像、场景走查报告、UAT 结论 | 向需求组反馈体验问题；UAT 不通过可拦下发布关口并记录 |
| 客户代表（客户代言） | 以客户价值与范围视角评审每阶段产出；管理客户期望与验收清单 | 客户评审意见、客户验收单 | 向产品/项目组提交；与发起人意见冲突时以发起人为准并留痕 |

运作规则：
- **单向交接**：下游只接收已评审通过的上游产出；发现上游问题走变更流程，不私自改需求或设计。
- **评审留痕**：每次评审的结论（通过/驳回/改哪条）记入对应文档的变更记录。
- **发起人关口**：每个阶段结束由产品/项目组汇总产出，发起人确认后才启动下一阶段；发起人提出的修改由对应组返工并重新提交。
- 在本项目中，上述各组由我方以对应角色分别承担：产出文档时标明出品组别，评审时换位以评审组视角自查，再交发起人。
- **客户与使用者关口**：每阶段产出在交发起人之前，必须附两份短评审 — 客户代表的《价值与范围评审》（做的是不是客户要的）和用户研究组的《可用性走查》（使用者能不能顺畅完成典型场景）；任一给出"不通过"，产出先返工，不带病上交。
- **视角独立性**：客户代表与用户研究组评审时只站在各自立场，不替开发进度让步；其意见即使被裁决驳回也完整保留在文档变更记录中。

## 贯穿全程的规范

- **文档即仓库资产**：所有设计文档进 `docs/` 并版本化，改设计先改文档、过评审，再改代码。
- **代码评审**：每次提交说明"改了什么、为什么、怎么验证的"；注释全中文（见 DECISIONS.md）。
- **CI 门禁**：三平台构建 + 单元测试 + clippy 全绿才合入；红灯不合入，无例外。
- **可验证汇报**：阶段汇报必须带实测数据（构建结果、测试结果、性能数字、截图），不报"应该没问题"。
- **原仓库红线**：123zpc/BlueLink 全程只读，不做任何修改。
