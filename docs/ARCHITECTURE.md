# 整体架构设计

> 版本：v0.1（评审稿）｜ 状态：待确认 ｜ 日期：2026-11-17
> 原则：分层单向依赖 — 上层依赖下层接口，下层不知道上层存在；平台差异只出现在最外层适配器。

## 一、分层总览

```
┌─────────────────────────────────────────────────────────┐
│ 表现层（前端 UI）                                        │
│ Tauri WebView 内的界面：视图、组件、前端状态             │
│ 只通过 IPC 命令/事件与后端通信，不碰蓝牙、不碰数据库     │
├─────────────────────────────────────────────────────────┤
│ 接口层（Tauri Commands / Events）                        │
│ 入参校验、DTO 转换、事件推送（消息到达、传输进度等）     │
├─────────────────────────────────────────────────────────┤
│ 应用服务层（用例编排）                                   │
│ 会话服务、聊天服务、传输服务、AI 服务、标记服务、设置服务 │
│ 一个用户动作 = 一个服务方法；负责事务与流程，不写细节    │
├─────────────────────────────────────────────────────────┤
│ 领域层（纯 Rust，零 IO）                                 │
│ 消息/会话/标签等实体、分片协议编解码、传输状态机、       │
│ 连接码算法、校验与重传规则 — 全部可单测，不依赖任何框架  │
├─────────────────────────────────────────────────────────┤
│ 基础设施层（适配器，实现领域层定义的接口）               │
│ 蓝牙传输（BLE 信令 + 平台高速通道）、SQLite 存储、       │
│ 文件系统、AI HTTP 客户端、系统通知/托盘、日志            │
└─────────────────────────────────────────────────────────┘
```

依赖规则：领域层不依赖任何其他层；应用服务层只依赖领域层接口；基础设施层实现接口、被依赖注入；表现层只认接口层的 DTO。换蓝牙库、换数据库、换 UI 框架，都不许波及领域层。

## 二、Rust 工作区划分（Cargo Workspace）

| Crate | 职责 | 对应层 |
|---|---|---|
| `bluelink-domain` | 实体、值对象、领域规则 | 领域层 |
| `bluelink-protocol` | 分片协议 v2 编解码、校验、状态机 | 领域层 |
| `bluelink-transport` | 传输接口定义 + BLE 实现 + 各平台高速通道后端 | 基础设施层 |
| `bluelink-storage` | SQLite 存储实现（消息、会话、标签、收藏、设置） | 基础设施层 |
| `bluelink-ai` | OpenAI 兼容客户端、流式处理、代理转发 | 基础设施层 |
| `bluelink-services` | 六大应用服务（会话/聊天/传输/AI/标记/设置） | 应用服务层 |
| `bluelink-app` | Tauri 壳：命令、事件、装配与启动 | 接口层 |
| `ui/`（前端工程） | 界面与前端状态 | 表现层 |

## 三、关键数据模型（概要，详细设计阶段展开）

- `Device`：设备标识、名称、蓝牙地址、历史连接信息
- `Conversation`：会话（与某设备的一对一会话，或一个 AI 会话）
- `Message`：消息（文本/文件/AI 回复），含引用关系、发送状态
- `TransferTask`：文件传输任务（分片进度、续传状态）
- `MessageMark`：消息标记的统一模型 — 标签、收藏、置顶都是一种 Mark，带类型与创建时间；这是 E1/E2/E5 能共用一套跳转定位机制的基础
- `Tag`：标签定义（名称、颜色），与 MessageMark 多对多关联
- `Settings`：分域设置（连接、下载、AI、外观）

## 四、关键机制

- **消息定位协议（支撑全部效率功能）**：前端虚拟列表按消息 ID 索引；任何"跳转到消息 X"请求走统一服务：查 X 的序号位置 → 虚拟列表滚动到该索引 → 渲染后高亮。标签、收藏、搜索、引用、置顶、AI 目录全部复用这一条链路，只许实现一次。
- **事件驱动**：后端状态变化（新消息、进度、连接变化）通过事件推送前端，前端不轮询。
- **传输状态机**：传输任务状态（待发/发送中/暂停/续传/完成/失败）在领域层显式建模，UI 只展示状态，不参与判定。
- **错误体系**：统一错误类型 + 中文用户提示映射；底层错误（蓝牙、IO、网络）不直接抛给界面。

## 五、三平台差异收敛点（仅限这些地方允许出现平台分支）

1. 蓝牙高速通道后端（Windows / Linux 用 RFCOMM，macOS 回落 BLE）
2. 打包与签名（各平台原生安装包）
3. 窗口与系统集成细节（标题栏、托盘、通知样式、快捷键修饰键）

其余代码三平台完全共用；CI 在三平台并行构建与测试，任何平台分支都必须有对应 CI 覆盖。

## 附录 A、核心数据字段（概要级，详细设计阶段定稿为表结构）

| 实体 | 关键字段 |
|---|---|
| Message | id（UUID）、conversation_id、direction、type、body、file_ref（文件消息）、reply_to_id（引用）、created_at（毫秒）、status |
| Conversation | id、kind（设备会话/AI 会话）、peer_device_id、title、last_read_message_id（阅读位置）、draft（草稿）、created_at、updated_at |
| Tag | id、name（唯一判定不区分大小写）、color、created_at、last_used_at |
| MessageMark | id、message_id、kind（标签/收藏/置顶）、tag_id（标签类必填）、created_at；唯一约束：同一消息 + 同一标签不重复 |
| TransferTask | id、message_id、file_name、total_bytes、done_chunks（分片位图）、sha256、state（状态机）、part_path |

## 附录 B、统一消息定位链路（E 组功能共用，只实现一次）

1. 调用方给出目标 message_id（来自标签、收藏、搜索、引用、置顶、目录或阅读位置）。
2. 标记服务按 message_id 查出 conversation_id 与该消息在会话内的序号（依赖 storage 的序号索引）。
3. 接口层通知前端切换会话并下发目标序号；前端虚拟列表滚动到该序号（未加载段按序号直接定位，不逐页翻）。
4. 目标消息渲染完成后，前端回执，后端/前端触发高亮（闪烁 2 次，约 1.6 秒，与 REQUIREMENTS 的 E1-09 一致）。
5. 任一步失败（消息已删等）返回明确错误码，前端按错误规范提示，不静默无反应。

## 附录 C、IPC 接口清单（草案，详细设计阶段定稿）

命令（前端→后端）：连接/断开、发送消息、发送文件、取消/续传传输、AI 提问/停止/重新生成、打标签/去标签、收藏/取消、置顶/取消、搜索、取历史分页、读写设置、按 ID 定位消息。
事件（后端→前端）：新消息、消息状态变化、传输进度、连接状态变化、AI 流式片段、AI 完成/出错。
