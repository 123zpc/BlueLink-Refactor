# 详细需求规格说明书

> 版本：v0.2（评审稿）｜ 状态：待确认 ｜ 日期：2026-11-17
> 本文是开发与验收的唯一对照标准：每条需求有唯一编号；开发做到某一条，照着条文实现；出问题时，照着条文的验收标准判定对错。
> 条文中写死的具体数值（上限、超时、时延等）均为拟定值，评审时可逐项改，改完以本文为准，不再口头约定。

## 〇、通用约定

- **编号规则**：功能需求 `F<功能号>-<序号>`，效率功能 `E<功能号>-<序号>`，非功能 `N-<序号>`，验收点 `AC-<需求号>`。一条需求只讲一件事。
- **消息**：每条消息有全局唯一 ID（UUID）、所属会话 ID、方向（发出/收到）、类型（文本/文件/AI 回复）、正文、发送时间（毫秒）、状态。消息一经发送成功，ID 与时间永不变更。
- **消息状态机**：发出消息只有四种状态 — 发送中 → 已送达 / 发送失败；收到消息只有 已接收。状态只能向前流转，失败可经"重发"回到发送中（生成新尝试记录，不改原 ID）。
- **时间显示**：今天的消息显示 `HH:mm`；昨天显示 `昨天 HH:mm`；今年内显示 `M月d日 HH:mm`；更早显示 `yyyy年M月d日 HH:mm`。悬停显示完整时间（含秒）。
- **本地性**：除 AI 接口调用外，全部数据只存本机；标签、收藏、置顶、草稿、阅读位置均为本机数据，**不发送给对方、不同步**。
- **删除级联**：消息被删除时，其标签、收藏、置顶、引用关系一并清理；会话被删除时，其全部消息与标记一并清理。删除均需二次确认。
- **文案**：所有用户可见提示为中文；错误提示必须包含"发生了什么 + 怎么办"，禁止只显示错误码或英文原文。

## 一、F1 设备发现与连接

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F1-01 | 启动后进入连接页，显示本机连接码：由本机蓝牙地址经哈希生成的 6 位数字，3+3 分组显示（如 `123 456`），旁边有一键复制按钮 | AC：任意机器启动可见连接码；同机多次启动连接码不变；点复制后粘贴内容为 6 位数字（无空格） |
| F1-02 | "等待连接"模式：点击后进入监听状态，页面显示等待动画与本机连接码；对方连入成功后显示对方连接码与设备名 | AC：监听中对方发起连接，3 秒内页面切换为已连接并显示对方信息 |
| F1-03 | "发起连接"模式：先蓝牙扫描附近可见设备并列出（设备名、地址、信号强弱），点击设备发起连接；也支持直接输入对方 6 位连接码连接（码用于本地配对校验与显示） | AC：扫描列表 10 秒内出现已开机可发现的测试设备；输入错误码时提示"连接码不匹配"且不建立会话 |
| F1-04 | 连接超时默认 15 秒（设置可调，范围 5–60 秒），超时显示"连接超时，请确认对方已开启等待连接"并可一键重试 | AC：对方未监听时发起连接，15±1 秒后出现该提示 |
| F1-05 | 断线自动重连：连接意外断开后自动重连 3 次，间隔依次 2 秒、5 秒、10 秒；期间界面显示"连接已断开，正在重连（第 n 次）"；3 次失败后停止并显示手动重连按钮 | AC：传输/聊天中断开对方蓝牙，界面按上述节奏提示；对方恢复后若在重连窗口内可自动恢复会话 |
| F1-06 | 同一时刻只允许一个对端连接；已有连接时新的连入请求被拒绝并在本机日志与界面留痕 | AC：第三台设备连入时被拒绝，已有会话不受影响 |
| F1-07 | 开发模式保留：输入 `000000` 可跳过蓝牙直接进入聊天界面（仅用于调试，正式版设置中默认关闭此入口） | AC：开关关闭时输入 000000 按普通错误码处理 |

## 二、F2 即时聊天

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F2-01 | 文本消息发送：输入框回车发送（可在设置中改为 Ctrl+回车发送，此时回车为换行）；单条上限 10,000 字符，超限时输入框计数变红且发送按钮禁用 | AC：粘贴 10,001 字符时无法发送且有明确计数提示 |
| F2-02 | 发送后消息立即上屏（乐观显示）并标记"发送中"；对方确认收到后变"已送达"；失败变红并可点击重发 | AC：断开连接时发送，消息显示发送失败；恢复后点重发可送达 |
| F2-03 | 接收消息：新消息到达时气泡上屏；若用户不在该会话或窗口不在前台，触发系统通知（内容为发送方名称 + 正文前 50 字）并在会话列表显示未读计数 | AC：后台时收到消息，通知与未读数均出现；进入会话后未读数清零 |
| F2-04 | 消息气泡支持：纯文本、链接识别（可点击，用系统浏览器打开）、代码片段等宽显示；禁止把对方发来的内容当作可执行代码运行 | AC：发送含 URL 的文本，链接可点且不影响气泡布局 |
| F2-05 | 历史加载：进入会话先显示最近 50 条；向上滚动到顶时自动加载更早 50 条，无需按钮；加载时保持当前阅读位置不跳动 | AC：1 万条历史的会话，连续上滑加载 5 次，画面无跳闪、无重复消息 |
| F2-06 | 消息操作菜单（右键或长按）：复制、引用、标签、收藏、置顶、删除，六项固定（详见 E 组各条） | AC：任意消息可调出菜单且六项可达 |
| F2-07 | 输入状态：对方正在输入时，会话顶部显示"对方正在输入…"，停止输入 3 秒后消失（该信令走信令通道，不落库） | AC：对方持续输入时提示存在，停手 3 秒后消失 |

## 三、F3 文件传输

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F3-01 | 发送方式：拖拽文件到聊天区、点击附件按钮选文件、粘贴文件，三种均可；发送前在输入区上方显示待发文件 chip（文件名、大小），可移除 | AC：三种方式均可发起；chip 信息与文件实际一致 |
| F3-02 | 无文件大小上限：实现必须流式传输，传 2 GB 文件时本进程内存增量 < 150 MB | AC：传 2 GB 文件全程采样内存，满足上限且传输完成、哈希一致 |
| F3-03 | 进度展示：文件气泡内显示进度条、已传/总量、实时速度（近 5 秒平均，每 200 ms 以内刷新一次）、预计剩余时间 | AC：传输中读数与实际字节数抽查一致，速度显示无 0 与实际值之间乱跳 |
| F3-04 | 取消：发送/接收双方均可取消自己一侧的任务；取消后 1 秒内停止传输，已传部分保留为 `.part` 临时文件供续传，气泡显示"已取消" | AC：取消后对端状态同步变为已取消；`.part` 文件存在且大小等于已传字节 |
| F3-05 | 断点续传：连接中断或取消后，同一文件再次发送时先协商已收分片，只传缺失部分；续传前校验 `.part` 的完整性，损坏则丢弃重传 | AC：传到 60% 时断网，重连后续传，实际传输字节约为剩余 40%（±5%），最终文件哈希一致 |
| F3-06 | 完整性：整文件 SHA-256 校验，接收完成后自动比对；不一致时文件不落入下载目录，气泡显示"文件校验失败"并可一键重新接收 | AC：人为篡改 `.part` 后续传完成，校验失败且正式文件不生成 |
| F3-07 | 接收落盘：默认存设置中的下载目录；同名文件自动命名为 `名(1).扩展名`、`名(2).扩展名` 递增，绝不覆盖已有文件 | AC：连发两个同名文件，得到原名与 (1) 两个文件，内容各自正确 |
| F3-08 | 选择性压缩：文本、代码等可压文件启用 zstd 压缩；图片、视频、压缩包等已压缩格式按文件头嗅探后原样直传 | AC：传 100 MB zip 时 CPU 占用与耗时明显低于全量压缩路径（以详细设计给定的基准值为准），传 100 MB 日志文本时实际传输字节显著小于原文件 |
| F3-09 | 队列：多个文件按添加顺序依次传输；单个失败不阻塞队列，失败项留在列表可单独重试 | AC：连选 3 个文件，中间一个断网失败，其余两个可完成 |

## 四、F4 AI 对话

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F4-01 | 配置：设置中填写接口地址、密钥、模型名；提供"测试连接"按钮，成功/失败均有明确中文结果；密钥本地加密存储，界面上以掩码显示 | AC：填错密钥点测试，提示为密钥类错误而非笼统失败；重启后配置仍在且密钥不以明文出现在配置文件中 |
| F4-02 | 流式输出：回复逐字渲染，收到片段后 100 ms 内上屏；渲染过程可随时向上滚动查看前文，滚动后不再强制拉回底部，用户点"回到底部"按钮才跟随 | AC：长回复生成中上滑，画面不被抢回；点回到底部后恢复跟随 |
| F4-03 | 停止生成：生成中显示停止按钮，点击后 1 秒内停止， 已生成部分保留并在末尾标注"（已停止）" | AC：停止后内容不再增长且标注出现，该消息可正常被标签/收藏 |
| F4-04 | 重新生成与版本：对 AI 回复可"重新生成"，新旧版本以 `< 1/2 >` 形式切换查看，默认显示最新版；用户消息可编辑后重发，其后回复随之重新生成 | AC：重新生成后版本切换可用，旧版本内容与首次生成一致 |
| F4-05 | 渲染质量：Markdown 全量渲染（标题、列表、表格、引用）、代码块语法高亮 + 一键复制、行内代码、公式不在首版范围；超长代码块可横向滚动不撑破气泡 | AC：用包含表格与代码块的标准测试文本渲染，版式与官方客户端对照无明显差异 |
| F4-06 | 多轮上下文：默认携带当前会话最近 20 条消息作为上下文（设置可调 0–100）；界面显示当前上下文条数；新建会话即清空上下文 | AC：调为 0 时 AI 表现为无记忆；调为 20 时第 21 条提问仍能引用第 1 条内容（以测试脚本为准） |
| F4-07 | 异常处理：断网、超时（默认 60 秒无响应判超时）、密钥错误、模型不存在、限流，五类错误分别给出中文提示与处理建议，回复位置显示重试按钮 | AC：逐项模拟五类错误，提示文案各不相同且均可重试 |
| F4-08 | 会话管理：AI 会话可新建、重命名、删除、按最近使用排序；与设备聊天会话在同一列表中以类型区分 | AC：三类操作即时生效，重启后保持 |

## 五、F5 AI 代理（核心思想，必须保留）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| F5-01 | 角色：已连接的两台机器中，有网且已配置 AI 的一台为代理端，无网一台为请求端；连接建立时双方自动协商并显示各自角色 | AC：两机连接后，界面正确显示"本机将通过对方使用 AI"或"本机正在为对方提供 AI" |
| F5-02 | 请求端在 AI 会话中提问时，请求经蓝牙发往代理端，代理端调用 AI 接口并把流式片段实时回传，请求端体验与本地 AI 一致（同 F4-02/03/04） | AC：请求端断网环境下完成一次流式问答，停止与重新生成均可用 |
| F5-03 | 代理端可见正在被使用的状态与本次会话的请求记录（时间、问题摘要），可随时在设置中关闭"允许对方使用本机 AI" | AC：关闭后请求端提问得到"对方已关闭 AI 代理"的明确提示 |
| F5-04 | 代理链路中断（蓝牙断开）时，正在生成的回复按 F4-03 的停止规则收尾并标注"（连接中断）" | AC：生成中断开蓝牙，请求端回复被正确收尾而非无限转圈 |

## 七、E 组 长对话效率功能（详细）

### E1 消息标签（核心新增，逐条验收）

| 编号 | 需求 | 验收标准 |
|---|---|---|
| E1-01 | 打标签入口共三处，行为一致：① 消息右键菜单"添加标签"；② 鼠标悬停消息时出现的工具条中的标签图标；③ 选中消息时按 Ctrl+T。三处均打开同一个标签编辑浮层 | AC：三处入口打开的浮层内容与行为完全一致 |
| E1-02 | 标签编辑浮层内容：已打标签以 chip 形式列出（带 × 可单个移除）；下方是输入框与已有标签候选列表（按最近使用排序）；在输入框输入新名称后回车即创建并打上；点候选标签即打上/取消（切换式） | AC：在浮层内可完成新建、打上、移除全流程，不跳出浮层 |
| E1-03 | 标签名规则：长度 1–20 个字符；首尾空格自动去除；纯空格不可创建；同名判定不区分大小写与首尾空格（`工作` 与 `工作 ` 视为同一标签）；不限制中英文与符号 | AC：逐项输入边界值验证，重复名不会产生两个标签 |
| E1-04 | 数量上限：单条消息最多 10 个标签，达到上限时浮层提示"每条消息最多 10 个标签"且不可再加；全局标签总数上限 500 个，达到时提示并引导先清理 | AC：加到第 11 个被拦截且提示出现 |
| E1-05 | 标签颜色：每个标签可设颜色，预设 10 色，默认第 1 色（灰蓝）；颜色只影响显示，不影响功能；改色全局生效 | AC：改色后所有带该标签的消息与标签面板同步变色 |
| E1-06 | 消息上的展示：已打标签在气泡下方以小 chip 显示（颜色点 + 标签名），超过 3 个时折叠为"+n"点击展开；chip 上的 × 仅在悬停时出现 | AC：打 5 个标签的消息展示为 3 个 chip + "+2" |
| E1-07 | 标签面板：主界面左侧栏设"标签"入口，点开为标签总览：每个标签显示名称、颜色、被标记消息数，按"最近使用在前"排序；顶部可按名称搜索标签 | AC：计数与实际标记数抽查一致；搜索可过滤 |
| E1-08 | 点击标签查看消息：点标签总览中的标签，打开右侧抽屉列出该标签下全部消息，按时间倒序；每条显示所属会话名、时间、内容摘要（文本前 100 字；文件显示文件名；AI 回复显示前 100 字） | AC：跨 2 个会话打同一标签，抽屉内两条都在且信息正确 |
| E1-09 | 点击定位（核心验收）：点抽屉中的任一消息条目，执行统一跳转：切换到其所属会话 → 虚拟列表按消息 ID 定位 → 该消息滚动到视口中央 → 背景高亮闪烁 2 次（总时长约 1.6 秒）后恢复；抽屉保持打开但不遮挡被定位消息 | AC：在含 10,000 条消息的会话中定位任意被标记消息，从点击到高亮完成 ≤ 500 ms；定位消息为视口中央±1 条之内；历史未加载段中的消息同样可达 |
| E1-10 | 标签管理：在标签总览中可重命名（全局生效，所有消息同步）、删除（二次确认，文案写明"仅删除标签，不删除消息"；删除只解除标记） | AC：重命名后旧名在任何消息上不再出现；删除后消息本体完好 |
| E1-11 | 标签不跨机：标签只存本机（见通用约定），对方界面不出现、传输协议不携带标签数据 | AC：抓包/查协议日志无标签字段；对方端无任何标签痕迹 |
| E1-12 | 空状态：无任何标签时，总览页显示中文引导"选中任意消息，右键或按 Ctrl+T 打第一个标签" | AC：全新安装打开标签页可见该引导 |

|---|---|---|

| E3-02 | 搜索框旁显示"第 i 个 / 共 n 个"；Enter 跳下一个、Shift+Enter 跳上一个，均走统一消息定位并高亮命中词；无结果时显示"无结果"且跳转按钮禁用 | AC：已知含 3 处命中的会话，计数为 3 且可逐个到达 |
| E3-03 | Esc 关闭搜索并清除全部命中高亮；搜索只作用于当前会话，跨会话搜索不在首版范围 | AC：关闭后高亮消失，再打开计数重新计算 |
